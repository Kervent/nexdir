# Security review — October 2026 (v0.4.0)

Scope: the desktop app (Rust backend, WebView frontend, Tauri configuration), the release
pipeline and the community tools. Method: code review of every IPC command and its
validation, the permission/capability files, preview and clipboard parsing, the threat model
items from the project brief, and automated dependency audits. Performed by the project's
development assistant on 2026-10-31; not an external audit.

## Findings

| # | Severity | Finding | Status |
|---|---|---|---|
| 0 | **High** | *Replace* wrote directly into the existing destination (`CopyFileExW` without `COPY_FILE_FAIL_IF_EXISTS`). Cancelling or any copy error made Windows delete the half-written file: the previous version was lost (reproduced). *Move* + *Replace* onto the same file under another name (8.3/hard link) could delete the only copy. Found in a follow-up review on 2026-10-31. | **Fixed**: staged copy via temp file, verification, `ReplaceFileW` with backup and rollback, same-file and link checks — [safe-copy.md](safe-copy.md). Shipped in v0.4.1; the earlier v0.4.0 build was discarded. |
| 0b | **High** | TOCTOU in the staged copy (found after 0.4.1): the temp name was checked first and created later; on failure Nexdir deleted the path, which could by then be another program's file. Backup removal and the source deletion after a move were also path-based. | **Fixed** in v0.4.2: exclusive `CREATE_NEW` temp files held without sharing, handle-bound renames and deletes, RAII ownership; `store.rs` likewise. Tests A–G in [safe-copy.md](safe-copy.md). |
| 1 | Medium | `validate_path` recognised device paths by text prefix only. `//./PhysicalDrive0` (forward slashes), `\\?\globalroot\…` (lower case), `\\?\Volume{…}` and `\\?\pipe\…` were accepted. Reaching a raw device would still need the file APIs to open it, but the check is meant to stop this at the boundary. | **Fixed**: decided by the parsed prefix kind; only drive and UNC paths (normal or `\\?\`) are allowed. Tests for every spelling. |
| 2 | Low | Path segments could contain `:` (NTFS alternate data streams, e.g. `notes.txt:hidden`), wildcards or control characters. Previews could read hidden streams; operations could target them. | **Fixed**: rejected in every segment. Tests added. |
| 3 | Low | `release.yml` interpolated `${{ github.ref_name }}` inside a script (found by a new workflow test in Phase 5). Only maintainers can push tags. | **Fixed** (Phase 5): passed via environment variable. A test now checks all workflows. |
| 4 | Info | The executable had no explicit `requestedExecutionLevel`; Windows defaulted to `asInvoker`. | **Hardened**: explicit manifest with `asInvoker`, Windows 10/11 compatibility and long-path awareness. |
| 5 | Info | A release could be built from a tag that does not match the app version. | **Hardened**: the Release workflow refuses mismatching tags; the packaging script only picks bundles with the current version in their name. |

## Checked without findings

- Every command validates its paths (`validate_path`/`validate_many`) or names (`validate_name`)
  before touching the file system; batch sizes are capped.
- Executables, scripts and shortcuts open only after confirmation, enforced in the backend.
- No generic file system, shell, HTTP or updater plugin is exposed; capabilities list only the
  app's own commands plus Tauri's default event/app/window permissions.
- CSP blocks remote content, inline scripts and frames; `freezePrototype` is on; the UI never
  uses `innerHTML`/`dangerouslySetInnerHTML`, `eval` or `window.open`.
- Preview: images as data URLs in `<img>` (SVG scripts cannot run), text as plain text, size caps.
- Clipboard (`CF_HDROP`) parsing stays within buffer bounds; every path is re-validated.
- Search index: bound parameters, quoted FTS5 terms, escaped LIKE wildcards (tested in Phase 3).
- Copy/move: links never followed, fail-if-exists Win32 calls, source deleted only after a
  verified copy, `remove_dir` instead of `remove_dir_all` (tests in Phases 1–2).
- Nothing deletes permanently; Recycle Bin only on fixed drives.
- Discord tools: tokens/webhooks only from environment or ignored `.env`, never printed;
  mentions disabled; webhook URL allow-list; workflows with least privilege and SHA-pinned actions.

## Not covered

- Fuzzing of the clipboard parser and the preview decoders.
- Dynamic testing of the WebView (e.g. trying to call commands from injected script) — the
  CSP and capability configuration were reviewed instead.
- Behaviour on network shares under attack (e.g. a malicious SMB server).
- The NSIS/MSI installers beyond their contents and version information (they were not
  installed on this machine).
