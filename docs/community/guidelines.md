# Community participation guidelines

These guidelines describe how we work together on GitHub and Discord. They add practical
detail to the [Code of Conduct](../../CODE_OF_CONDUCT.md), which always applies.

## Where things happen

| Topic | Place |
|---|---|
| Questions about using Nexdir | Discord #support forum (one post per question) |
| Bug reports | GitHub issue (*Bug report* form) — or Discord #bug-reports if you're unsure; the Support Team moves confirmed bugs to GitHub |
| Feature ideas | GitHub issue (*Feature request*) or Discord #feature-requests for early discussion |
| Pre-release feedback | GitHub issue (*Pre-release feedback*) |
| Security vulnerabilities | **Privately** via a GitHub security advisory — see [SECURITY.md](../../SECURITY.md). Never in public issues or Discord. |
| Code and docs changes | Pull requests |
| Technical decisions | GitHub issues and pull requests, so everyone can follow them later. Discord chats are for discussion; the outcome is written down on GitHub. |
| Releases, milestones, selected issues | Announced automatically in Discord #releases, #roadmap and #github-updates |

## Ways to help

| Area | How to start |
|---|---|
| **Software development** | Pick an issue labelled `good first issue` or `help wanted`, comment that you'd like to work on it, then follow [your first contribution](../development/first-contribution.md). |
| **Beta testing** | Get the *Beta Updates* role on Discord, install pre-releases on a test machine or with copies of your files, and report with the *Pre-release feedback* form. |
| **Community support** | Answer questions in #support. Reproduce bug reports and add missing details (Nexdir version, Windows version, steps). |
| **Documentation** | Fix unclear or outdated docs with a pull request, or open a *Documentation* issue. Small fixes need no issue. |
| **Translation** | Nexdir's interface is English-only for now. Translation support is planned; until then, help by keeping UI text short and clear, and say hello in #contribution-help so we can contact you when it starts. |
| **Moderation** | Report problems to moderators, welcome newcomers, and apply for the Moderator role if you'd like to help more ([team roles](team-roles.md)). |

On Discord, the optional "Interested: …" roles show what you'd like to help with.

## Good practice

- **Search first.** Many questions and ideas already have an issue or a post.
- **One topic per issue or post.** It keeps the discussion findable.
- **Say when you start working on an issue**, and say when you stop. Unclaimed issues are free for
  anyone; claims without activity for 2 weeks may be released by a maintainer.
- **Keep pull requests small and focused.** Large changes: open an issue first and agree on the
  approach, so nobody's work is wasted.
- **Be patient with reviews.** Maintainers are volunteers. A friendly ping after a week is fine.
- **Disagree about ideas, never about people.** Explain your reasoning and stay open to others.
- **Use English** in issues, pull requests and the main Discord channels, so everyone can follow.

## Privacy and safety

- Never post personal files, private paths with your name, passwords, tokens or webhook URLs —
  not in issues, logs, screenshots or Discord. Blur or crop screenshots.
- Never use your only copy of important files to test a pre-release.
- Don't share other people's private information.
- Don't mention `@everyone` or `@here`; announcements use opt-in notification roles.

## AI-assisted contributions

Using tools to help write code or text is fine. You are responsible for what you submit:
understand it, test it, and make sure you have the right to contribute it under the MIT license.

## Recognition

Everyone with a merged contribution — code, docs, design, translation — is a contributor. Ask
on Discord for the *Contributor* role and link your merged pull request.
